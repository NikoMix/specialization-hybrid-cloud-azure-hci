## What the Auditor Checks

The auditor verifies that your organisation has **structured onboarding assets and delivery templates** for the Azure Local / hybrid infrastructure services you sell and deliver — demonstrating that you enable customers systematically, not just reactively.

**Typical questions:**
- What onboarding materials do you provide to new customers?
- Do you have standard templates for Azure Local cluster delivery?
- How do you ensure customers can operate Azure Local infrastructure independently after handover?

## Evidence Guidance

### Customer Onboarding Pack

The onboarding pack should include or cover:

- **Introduction to your organisation** — team structure, key contacts, escalation path
- **Engagement overview** — scope, timeline, milestones, deliverables (site survey, BoM, deployment, validation, handover)
- **Communication cadence** — meeting frequency, reporting format, tools used
- **Azure environment standards** — naming conventions, tagging policies, governance baseline, Azure landing zone alignment
- **Azure Local environment standards** — cluster naming, RBAC model, monitoring baseline, patching cadence (Azure Update Manager)
- **Support model** — how ongoing support works post-go-live (incident response, SLAs, hardware vendor escalation)
- **Key contacts** — project lead, technical lead, Azure support paths, hardware vendor support

### Delivery Templates

Provide templates from at least two of the following categories:

| Category | Example Template |
|---|---|
| Discovery | Site survey questionnaire, stakeholder map, Azure Local readiness assessment, capacity / sizing workbook |
| Design | High-Level Design (HLD) template, Azure Local cluster design document, network topology template, Azure landing zone alignment record |
| Build | Deployment runbook, cluster validation script set, Network ATC intent definition, Azure Update Manager configuration |
| Test | Validation test plan template, performance test report template, DR failover test script |
| Deploy | Go-live checklist, hypercare plan template, rollback procedure, cluster handover checklist |
| Handover | Closure report template, knowledge transfer agenda, support handover checklist, ongoing managed service SOW |

### Knowledge Transfer Plan

A knowledge transfer plan should cover:

| Item | Details |
|---|---|
| **Scope** | What the customer needs to know to operate independently — Azure Local lifecycle (firmware + OS), Arc enrolment, monitoring, backup / DR runs |
| **Format** | Documentation, hands-on workshops, recorded sessions |
| **Recipients** | Customer IT operations team, infrastructure leads, security team |
| **Timeline** | Integrated into the final delivery phase |
| **Validation** | How you confirm the customer can operate the cluster — e.g. a witnessed patch cycle or DR test |

### Operational Runbook for an Azure Local Cluster

An operational guide (anonymised) for an Azure Local cluster should include:
- Cluster architecture overview (nodes, network, storage, Arc enrolment)
- Day-to-day operational tasks (health checks via Azure Monitor, capacity reporting)
- Monitoring and alerting setup (Azure Monitor, Log Analytics, Insights for Azure Local)
- Patching and lifecycle (Azure Update Manager, firmware/driver updates from OEM, solution updates)
- Backup and DR runbooks (Azure Backup for Azure Local VMs, Azure Site Recovery failover)
- Common issues and resolutions (storage rebalancing, node maintenance mode, Arc agent troubleshooting)
- Escalation contacts (Microsoft Support, OEM hardware support, your support team)
- Cost management guidance (Azure Local consumption meters, Azure Hybrid Benefit, reserved capacity)

## Sample Onboarding Timeline

| Week | Activity | Deliverable |
|---|---|---|
| 0 | Kickoff and access provisioning | Kickoff deck, environment intake form |
| 1 | Site survey and discovery workshops | Site survey report, sizing workbook, stakeholder map |
| 2 | BoM and procurement | Validated hardware quote, procurement timeline |
| 3–4 | Design and design sign-off | HLD, network topology, Azure landing zone alignment |
| 5–N | Hardware delivery, rack & stack, cluster deployment | As-built document, validation test results |
| N+1 | Workload migration / onboarding | Migration plan executed, workloads live on cluster |
| N+1 | UAT, validation, knowledge transfer | Validation report, training sessions delivered |
| N+2 | Go-live and hypercare | Hypercare log, support handover |
| N+4 | Closure and managed service transition | Closure report, ongoing SLA / managed service SOW |

## Common Gaps

| Gap | Remediation |
|---|---|
| No formal onboarding pack | Create a branded PowerPoint with the sections listed above — 10 slides is sufficient |
| Templates exist but are customer-specific | Generalise one customer's artefacts into a reusable template |
| Knowledge transfer is verbal only | Create a one-page KT plan template; even a checklist format is accepted |
| Operational runbook not documented | Export Azure Monitor dashboards and create a 5–10 page operational summary for one delivered cluster |
| No validation that the customer can operate independently | Document a witnessed patch cycle or DR test as proof of successful knowledge transfer |
