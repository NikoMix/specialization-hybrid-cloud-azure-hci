Module B is where the Hybrid Cloud Infrastructure with Microsoft Azure Local
specialization is actually won or lost. Every control here needs technical
evidence from real customer engagements — Azure Local clusters on validated
hardware, Arc-enrolled and wired into Azure Monitor, Backup and Site Recovery.

| Section | Control | What it proves |
|---|---|---|
| 1 – Capability | [1.1 Azure Local implementation capability](1-1-azure-local-implementation/) | You can design, deploy and operate Azure Local for customers |
| 2 – Performance | [2.1 ACR performance](2-1-acr-performance/) | Measured Azure consumption in the eligible hybrid categories |
| 2 – Performance | [2.2 Customer diversity](2-2-customer-diversity/) | The consumption comes from multiple unique customers |
| 3 – People | [3.1 Certifications](3-1-certifications/) | Certified individuals hold the required exams |
| 4 – Submission | [4.1 Audit readiness & evidence package](4-1-audit-readiness/) | The package is complete, indexed and internally reviewed |
| 4 – Submission | [4.2 Partner onboarding assets](4-2-partner-onboarding/) | Repeatable onboarding, delivery and knowledge-transfer assets exist |

## Where the technical evidence comes from

Module B evidence is a by-product of delivery, not a document-writing exercise.
The [engagement playbook](../engagement/) produces the architecture diagrams,
HLDs, LLDs, runbooks and knowledge-transfer plans that satisfy B.1.1 and B.4.2,
and the [reference architectures](../engagement/reference-architectures/) page
maps each delivered pattern to the official Azure Architecture Center article
the auditor can check it against.
